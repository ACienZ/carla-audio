## 01：先生成一个正弦波

**目标：** 理解“时间数组如何变成声音”，运行 [01_sine_wave.py](01_sine_wave.py)。

正弦波在正负振幅之间周期性变化。频率决定每秒振动次数，振幅表示波形的大小：

```text
s(t) = A × sin(2πft)
```

| 公式中的量 | 代码 | 本例含义 |
| --- | --- | --- |
| A | AMPLITUDE | 振幅 0.75，数字波形峰值为满幅的 75% |
| f | FREQUENCY_HZ | 440 Hz，每秒振动 440 次 |
| t | times | 各个采样点对应的秒数 |
| s(t) | audio | 每个采样时刻的波形值 |

计算机不能保存无限多个时刻，因此每秒取 48000 个点。第 n 个点对应：

```text
t[n] = n / SAMPLE_RATE
n = 0, 1, 2, ..., 479999
```

这里有两个不同的“频率”：440 Hz 是声音的振动频率；48000 Hz 是记录波形的采样率。`np.arange(total_samples)` 创建采样编号，除以采样率得到时间数组，`np.sin(...)` 就对每个时刻分别计算振幅。

本例 `audio` 取值在 -0.75 到 0.75 之间。保存时直接转为 `np.float32`，通过 `wavfile.write()` 写入 32-bit 浮点 WAV，不乘以 32767，也不转换为 16-bit 整数。SciPy 根据数组类型决定 WAV 的浮点或 PCM 格式；一维数组表示单声道。WAV 同时保存采样率等信息，播放器据此还原时间顺序。数字振幅没有在这里校准成实际声压或分贝，播放音量还取决于设备设置。

```bash
python 01_sine_wave.py
```

预期听到持续的 440 Hz 固定音调，音量保持稳定。它不是完整的救护车音色。02、03 也使用 440 Hz，04 的声源频率仍为 520 Hz。

## 02：只加入距离衰减

**目标：** 理解为什么越近声音越大，运行 [02_distance_attenuation.py](02_distance_attenuation.py)。

ego 静止，救护车在后方 220 米处，以 20 米/秒接近。暂不考虑声音传播需要的时间，直接使用接收时刻 t 的距离：

```text
d(t) = d₀ − vt
     = 220 − 20t
```

自由场中的理想点声源向四周传播，能量分布到面积随距离平方增长的球面上，因此声强近似按 `1/d²` 减小。声强与声压振幅的平方成正比，所以波形振幅按 `1/d` 衰减。这里调整的是波形振幅，使用距离倒数。[声强与振幅原理](https://openstax.org/books/university-physics-volume-1/pages/17-3-sound-intensity)

以 10 米作为参考距离，使用增益：

```text
g(d) = reference_distance / max(d, reference_distance)
y(t) = A × g(d(t)) × sin(2πft)
```

| 时刻 | 距离 | 增益 | 波形振幅 A × g |
| --- | --- | --- | --- |
| 0 秒 | 220 米 | 1/22 | 约 0.03409 |
| 5 秒 | 120 米 | 1/12 | 0.0625 |
| 10 秒（窗口终点） | 20 米 | 1/2 | 0.375 |

10 秒是输出窗口终点，不另存该时刻的采样点，因此最后一点距离约为 20.00042 米，增益略小于 1/2。当前片段不会到达 10 米参考距离；10 米以内增益保持 1 的约定仍保留，但本次没有触发。该增益上限不是完整的近场声学模型。

| 公式中的量 | 代码 |
| --- | --- |
| d₀、v | INITIAL_DISTANCE_METERS、APPROACH_SPEED_MPS |
| d(t) | distances |
| reference_distance | REFERENCE_DISTANCE_METERS |
| g(d)、y(t) | gain、audio |

```bash
python 02_distance_attenuation.py
```

预期音调始终为 440 Hz，与 01 相同，音量逐渐增大。与 01 一样，直接将浮点波形转为 `np.float32`，用 `wavfile.write()` 保存，不乘以 32767。这里保留人为隔离的“只衰减”效果，尚未包含有限声速。

## 03：只加入运动中的传播

**目标：** 理解接收时间为什么不同于发声时间，运行 [03_sound_propagation.py](03_sound_propagation.py)。本步保持振幅固定，不做距离衰减。

定义两个时间，它们使用同一个仿真时钟：

- u：救护车发出声音的时刻，对应 `emission_times`。
- t：ego 听到这段声音的时刻，对应 `receive_times`。

ego 不动，因此声音走过的路径就是救护车发声时到 ego 的距离。声速为 c = 343 米/秒，传播耗时等于路径长度除以声速：

```text
d(u) = d₀ − vu
t = u + d(u)/c
```

每个音频采样点已经知道接收时间 t，需要反求发声时间 u。代入并逐步整理：

```text
t = u + (d₀ − vu)/c
ct = cu + d₀ − vu
ct − d₀ = (c − v)u
u = (ct − d₀)/(c − v)
```

代码中的 `SPEED_OF_SOUND_MPS` 就是 c。将求得的 `emission_times` 放入声源正弦波：

```text
y(t) = A × sin(2πfu)
```

当前 03 的初始距离为 220 米、速度为 20 米/秒。接收时刻 t = 0 对应 u = -220/323 ≈ -0.681115 秒。意思是“录制开始时听到的声音，在约 681 毫秒之前已经发出”。我们假设声源录制前已持续发声，并在这段历史内保持同样的接近速度，因此正弦波直接计算负时间，不添加开头静音。

将 u 的公式放入相位，可以直接看出时间缩放：

```text
2πfu = 2π × [f × c/(c − v)] × t − 2πf × d₀/(c − v)
```

第一项给出接收频率，第二项是固定相位偏移：

```text
f_received = f × c/(c − v)
           = 440 × 343/323
           ≈ 467.24 Hz
```

若 v = 0，得到 u = t − d₀/c，只剩固定时移，频率仍为 440 Hz。若救护车接近，后发出的波峰传播距离更短，到达间隔被压缩，听到的频率升高。模拟这一传播时间变化后，不再额外做一次多普勒变调。

```bash
python 03_sound_propagation.py
```

预期音量稳定，相对 01 的 440 Hz 纯音升高约 6.19%；02 也是 440 Hz，但另有音量衰减。因为本例以 20 米/秒匀速沿直线接近，升高后的音调也保持稳定，不会随着距离减小持续升高。输出仍为 16-bit PCM，以本例公式与数值核对为准。

## 04：将两者结合

**目标：** 计算同时包含传播和衰减的接收声音，运行 [04_combined.py](04_combined.py)。

先使用第 3 步的方法求发声时间，再根据那一刻的位置计算传播距离。本例仍使用原参数：520 Hz、初始 30 米、速度 2 米/秒，不直接沿用当前 03 的数值：

```text
u = (ct − d₀)/(c − v)
path_distance = d₀ − vu
gain = reference_distance / max(path_distance, reference_distance)
y(t) = A × gain × sin(2πfu)
```

`emission_times` 对应 u，`path_distances` 对应路径长度，`gain` 对应振幅增益，`audio` 对应接收波形。

在计算方法上，02 为了单独展示衰减，使用当前时刻 t 的距离；04 使用发声时刻 u 的距离。当前声音来自稍早、更远的位置，振幅也应按这条传播路径计算。例如本例 t = 0 时路径约为 30.176 米，而不是当前的 30 米。02 已改为 220 米、20 米/秒，本例仍为 30 米、2 米/秒，不能直接将两份输出的振幅差异当作传播延迟的影响。

```bash
python 04_combined.py
```

预期音量逐渐增大，频率约为 523.05 Hz。当前 03 输出约 467.24 Hz，二者声源频率与速度不同。只有声源、初始距离、速度和其他参数相同时，才可比较加入传播后的振幅与“仅衰减”的差异；当前 02、04 参数不同。默认不加淡入淡出，四份音频开头和结尾的直接截断可能产生短暂点击声；这与中间波形是否连续是不同的问题。

## 然后再看仿真距离数据

**距离本身不能决定声音内容。** 首先要指定声源 s(u)，可以是正弦波、双音警笛或真实录音。距离记录决定何时听到它、衰减多少。本节将 s(u) 定义为单位振幅波形，整体振幅系数 A 单独相乘。

四个例子知道匀速公式 `d(u) = d₀ − vu`。读取 CARLA 数据时，不需要假定整段匀速，而是利用每个测量点提供的时间和距离。

对于 ego 静止的情况，处理顺序是：

1. 原始时间戳减去首条时间戳，得到相对时间 uᵢ，并保留对应距离 dᵢ。
2. 相邻测量之间线性插值，构造近似连续的 d(u)。每段的斜率可以不同。
3. 计算各测量时刻发出的声音何时到达：`tᵢ = uᵢ + dᵢ/c`。
4. 对完整音频的每个接收时刻 t，在这组到达时间中找到所在区间，反插值求发声时刻 u(t)。
5. 再插值得到发声时刻的距离，计算 `y(t) = A × g(d(u(t))) × s(u(t))`。

这里把测量时刻视为候选发声时刻，是为了计算传播；不是把 sensor 的数据接收延迟当作声音传播延迟。所有时间使用仿真时间，网络延迟不进入声学公式。

### 救护车速度时刻变化时

举一个便于计算的假设记录，表中 1 秒间隔只用于说明，实际输入约为 0.05 秒：

| 测量时刻 | 距离 | 该点的声音到达时间 uᵢ + dᵢ/343 |
| --- | --- | --- |
| 0 秒 | 30 米 | 约 0.08746 秒 |
| 1 秒 | 28 米 | 约 1.08163 秒 |
| 2 秒 | 24 米 | 约 2.06997 秒 |

第一段平均接近速度为 2 米/秒，第二段为 4 米/秒，因此两段的距离变化和时间映射斜率不同。第二段多普勒更明显，不需要先求一个全程平均速度再合成。

例如第二段的发声时刻 u = 1.5 秒，插值得到距离 26 米，对应到达时间 t = 1.5 + 26/343 ≈ 1.57580 秒。反过来，为了计算 t = 1.57580 秒听到的声音，就回到 u = 1.5 秒的声源波形，并按 26 米路径衰减。

上级完整脚本中的 `calculate_propagation()` 已按所有测量区间做这种映射。只在录制开头没有历史记录时，使用前两条测量的变化率外推所需的短暂历史。实际数据尚未做变速场景采集，这个说明不等于新增变速 CARLA 实测。

20 Hz 距离记录不能恢复两个测量点之间的全部真实运动。线性插值相当于把每个区间内的距离变化近似为匀速；急加速或急转弯等快速变化需要更密的轨迹记录。速度变化不大时，这个分段近似便于起步；它不是对任意运动都精确的声学仿真。

### 如果 ego 也在移动

此时不能直接用同一时刻的两车距离代替传播路径。声音从救护车发声时的位置出发，到达 ego 接收时的位置：

```text
c × (t − u) = |source_position(u) − microphone_position(t)|
```

竖线表示两点间的三维欧氏距离。左边是传播时间乘声速，右边是跨两个时刻的实际传播路径。

sensor 当前记录的只有 `|source_position(u) − microphone_position(u)|`，没有告诉我们麦克风在 t 时刻到了哪里。所以，仅有双方同一时刻的距离通常不足以精确计算移动接收者的声音；后续需要保存双方带时间戳的位置轨迹。本轮不修改 sensor 或采集格式，先理解静止 ego 的链路。
